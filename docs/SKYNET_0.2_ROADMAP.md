# SKYNET 0.2 — пошаговая версия

Версия 0.2 переводит SKYNET из прототипа ИИ-института в управляемую платформу:
роутинг становится строже, появляется отдел контроля качества, Docker-деплой
получает технические ограничения, а проект — базовые тесты и CI.

## Шаг 1. Зафиксировать ядро института

Цель: сохранить текущую удачную архитектуру `router -> department -> crew -> tasks`,
но убрать хрупкие места.

- Роутер возвращает только известные отделы.
- Есть fallback по ключевым словам, если LLM-классификация недоступна.
- Отделы регистрируются в одном месте.
- Финальный ответ может проходить через контроль качества.

## Шаг 2. Добавить отдел контроля качества

Новый отдел `quality_control_dept` проверяет итог до выдачи пользователю:

- соответствует ли результат исходному запросу;
- есть ли выдуманные факты, опасные действия или слабая инструкция;
- что надо исправить перед продакшеном;
- можно ли отдавать результат пользователю.

Это будущая база для контролирующего отдела, который будет принимать работу
маркетинга, дизайна, кодеров и новых отделов.

## Шаг 3. Усилить безопасность Docker-деплоя

Главный риск 0.1 — автономный запуск сгенерированного кода.
В 0.2 деплой получает технические ограничения:

- безопасная нормализация Docker image/container tag;
- whitelist переменных окружения вместо передачи всего `.env`;
- лимиты CPU/RAM;
- управляемый сетевой режим контейнера;
- защита путей внутри `OUTPUT_DIR`.

## Шаг 4. Добавить тестовую базу

Минимальный набор тестов проверяет то, что нельзя доверять LLM:

- нормализация Docker tag;
- защита от выхода за пределы рабочей директории;
- whitelist секретов;
- fallback-роутинг по ключевым словам.

## Шаг 5. Добавить CI

GitHub Actions должен запускать:

- установку проекта;
- `pytest`;
- `compileall` для проверки синтаксиса пакетов.

## Шаг 6. Следующая версия 0.3

После 0.2 стоит добавить:

- FastAPI API для запуска задач;
- web-панель статусов и логов;
- очередь задач;
- хранилище запусков;
- роли доступа;
- RAG-базу знаний вместо одних markdown-уроков;
- eval-наборы для каждого отдела;
- GitHub PR-режим: агент не пушит напрямую, а открывает PR.

## Рекомендуемый порядок внедрения

1. Установить зависимости: `pip install -e . pytest`.
2. Запустить тесты: `pytest`.
3. Проверить роутер на 3-5 запросах без деплоя.
4. Включить контроль качества: `ENABLE_QUALITY_GATE=1`.
5. Проверить Docker-деплой на тестовом агенте.
6. Только после этого переносить на сервер.
