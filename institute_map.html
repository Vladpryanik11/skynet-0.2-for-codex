Институт SKYNET

СХЕМА №1 — ОРГАНИЗАЦИЯ ОТДЕЛОВ
Диспетчер + 4 отдела · sequential CrewAI

Один запрос — три возможных адреса. Диспетчер читает, что вы просите, и передаёт задачу нужному отделу. Внутри каждого отдела цепочка специалистов работает строго по очереди, а в конце — «Аналитик самообучения», который запоминает, что сработало.

Как читать схему

Сплошная стрелка — агент передал результат следующему
Пунктирная рамка — менеджер: раздаёт задачи, сам их не делает
Пунктирная линия сбоку — урок из базы знаний учитывается в следующем запуске

Три отдела

Участок 01

Кодеры

Проектирует, пишет и деплоит новых ИИ-агентов по текстовому запросу.

Результат: agent.py + запущенный Docker-контейнер
Участок 02

Маркетинг + копирайтеры

Превращает запрос в бриф и готовый рекламный/маркетинговый текст.

Результат: готовый текст под канал (пост, email, лендинг)
Участок 03

Дизайнеры

Разбирает референсы (Pinterest/Dribbble/Awwwards) и собирает макет.

Результат: design-system.md + рабочий index.html

Простыми словами

Каждый отдел — это не один ИИ, а маленькая команда из нескольких ИИ-специалистов, которые передают работу друг другу по очереди, как на настоящем производстве: один придумал план, следующий сделал по плану, третий проверил. В конце «Аналитик самообучения» записывает, что в этот раз получилось хорошо или плохо, в обычный текстовый файл. В следующий раз вся команда отдела заглядывает в этот файл — и не наступает на те же грабли.
Технические детали (для тех, кому интересно)

Вся система написана на Python поверх фреймворка CrewAI. Каждый отдел — отдельный файл crew.py, все вместе они лежат в src/ и подключаются через один общий диспетчер src/institute/router.py.

  • Диспетчер — один быстрый вызов дешёвой модели (Haiku), которая решает, в какой отдел идёт запрос.
  • Конвейер отдела (Process.sequential) — задачи получают контекст только от явно указанных предыдущих этапов.
  • База знаний (knowledge_sources) — локальные уроки отделов; CrewAI memory включается отдельно и по умолчанию выключена в local-режиме.
  • Каждая роль может работать на своей модели (Claude/GPT) — настраивается переменными окружения в .env, без правки кода.
